# Crucible AI 审计平台 — 节点解耦与模块化设计方案（仅设计，不改代码）

## 一、调研结论：现状与核心耦合点

当前是「带分支出口的 6 节点线性链」：`orchestrator.run_orchestration`（backend/app/contexts/agent/orchestrator.py:297）顺序执行 `NODE_ORDER`，每节点落 `NodeRun`（input_json/output_json）支撑断点续跑。已有 `NodeExecutor` Protocol（nodes/base.py:76），但解耦不足：

| # | 耦合点 | 位置 |
|---|---|---|
| C1 | 节点身份注册重复 **7 处**，靠人工同步 | orchestrator.py:43 `NODE_ORDER`；task/service.py:23 `_NODE_INDEX`/`_RETRYABLE_FROM_NODES`；ai_runner.py:51 `NODE_OUTPUT_SCHEMAS`；infrastructure/agent-runner/runner/node_schemas.py:19 `NODE_INPUT_SCHEMAS`；run_one.py:574 `NODE_AI_KEYS`；前端 meta.ts/NodeSteps.tsx/api.ts 三处 |
| C2 | 数据交接无类型：`previous_outputs: dict[str,dict]` 靠约定按键取值 | reproduce.py:28-43 硬依赖 `env_ready.target_url` 等；契约只存在于注释/SKILL.md |
| C3 | 编排循环内 **6 处按节点名硬编码分支** | orchestrator.py:334(`node_index>=2` 非web)、350/359/415(`=="source"`)、362/474(`=="audit"` gate出口)、431(`=="report"` 失败保留结论)、91/114(`NODE_ORDER[4]` 裸索引) |
| C4 | 校验/Mock 按节点名 if/elif 集中在执行层 | ai_runner.py:83 `_mock_output`、544 `validate_output` |
| C5 | verdict 领域规则放在 ai_runner，被 report.py/tasks.py 跨层 import，`_CONFIRMED_VERDICTS` 两处重复 | ai_runner.py:37-44、tasks.py:63 |
| C6 | 节点直接持有 `ctx.db_session` 做各种 IO，env_ready 甚至 SQL 直更 `node_index==2` 的 attempt | env_ready.py:1026-1043 |
| C7 | 节点契约三处副本无机器同步 | spec 文档表 / 后端 required+optional dict / 镜像内 MCP JSON schema |

**新增一个 AI 节点目前要改 11 处（跨 4 个代码库区域）。**

## 二、设计决策（问题未获答复，按推荐项采用，均可替换）

1. **编排形态：线性链 + 声明式出口**。不重写为 DAG 引擎，保留断点续跑/取消语义与 test_orchestrator 兼容；但节点声明数据依赖（`requires`），未来需要并行时只换调度器、不动节点。
2. **镜像策略：镜像内置 + 构建期同步 + 契约测试**。SKILL.md/MCP schema/工具策略仍打进 agent-runner 镜像，单一真相移到后端节点包，构建期复制进镜像，测试断言两侧一致。不把 prompt 放进运行时数据面。
3. **框架优先**：契约为所有未来节点类型（分析类/链路深化/后处理）预留统一形态。

**兼容性红线**：本方案零数据库 migration（NodeRun 表不变）、API 响应与 SSE 事件形状不变、`.node.json`/`.node_output.json` 文件协议不变。

## 三、目标架构：三层解耦

```
┌─ 编排层 orchestrator.py ─ 通用循环：检查点/取消/事件/落库
│   只认 NodeSpec + 声明式出口策略，无任何 node_key if 分支
├─ 节点层 nodes/<key>/ ─ 每节点一个自包含包（executor + contract + SKILL.md）
│   contract.py：Input/Output pydantic 模型 + 校验器 + MCP schema + mock 工厂
│   registry.py：NodeSpec 有序注册表（唯一顺序真相）
├─ 领域层 verdict.py ─ verdict 权威规则（从 ai_runner 下沉）
└─ 运行层 ai_runner / core/agent_runner.py ─ 节点无关：起容器/流事件/形状回喂环
```

## 四、节点契约标准（核心：标准入参与出参）

### 4.1 标准入参 = 运行时上下文 + 类型化数据交接（两部分分离）

- **NodeContext（运行时信封，所有节点一致）**：`task_id/run_id/host_workdir/source_path`、任务字段、`runner_env`、`on_event`、`services`（见 §6.2）。不再暴露裸 `db_session`（过渡期保留但标记 deprecated）。
- **inputs（类型化交接）**：节点在 contract 中声明 `requires`（依赖的上游 node_key 集合）+ 各上游的 Output 模型。orchestrator 在执行前把上游 output_json 解析为 pydantic 实例注入 `ctx.inputs`，节点内用 `ctx.inputs["source"].workspace_path` 取代 `previous_outputs["source"]["workspace_path"]`。解析失败＝上游契约破裂，走现有 corrupt-output 失败路径。落库的 `input_json`（`_handoff_input` 的完整 previous 快照）形状不变。

### 4.2 标准出参 = 每节点一个 Output pydantic 模型

orchestrator 落库前统一 `model.validate(output)`（替代 ai_runner 的 if/elif 分派）；条件必填规则（如 audit pass 才需要 kill_chain）用 `@model_validator` 表达，**错误消息逐字迁移**（测试以文案子串断言，文案即契约）。`model_dump()` 后仍存 JSON，`NodeRun.output_json` 不变。

### 4.3 六节点契约表（标准入参 = executor 组装进 input_json 的字段；出参 = output_model 字段，* 必填）

| 节点 | kind | requires | 标准入参 | 标准出参 |
|---|---|---|---|---|
| source(0) | code | – | project_address, project_ref（来自 Task） | repo_dirname*, project_path*, source_path*, workspace_path*, commit_sha, host_workdir |
| profile(1) | ai | source | hints（规则引擎画像）, source_path | is_web*(bool), language, framework, port, has_dockerfile, has_compose, detected_services, start_command, non_web_reason |
| env_ready(2) | ai | source, profile | source_path, commit_sha, profile 全量 | target_url*, compose_path*, initial_creds*, transport_shape, started_containers |
| audit(3) | ai | source, profile | source_path, vulnerability_description, profile | gate_verdict*(pass/fail/uncertain), gate_reason*；pass 条件必填：kill_chain, payloads, runtime_dependent, core_claim；runtime_dependent=true 条件必填：unresolved_facts |
| reproduce(4) | ai | source, env_ready, audit | source_path, target_url(容器改写), initial_creds, transport_shape, compose_path, started_containers, audit 全量, vulnerability_description | verdict*(6档), reproduced*(bool), attempts*；可选：evidence, screenshots, cvss, vulnerable_file, poc；禁止 report_data |
| report(5) | ai | profile, env_ready, audit, reproduce | profile, env_ready, audit, reproduce(剔除report_data), vulnerability_description, project_address, expected_verdict, document_kind | report_data*(document_kind+8节), final_verdict*(7档且不得漂移)；confirmed 条件必填 cvss；authored_by="reporter" |

### 4.4 MCP schema 与 pydantic 的关系（受网关约束）

submit_result 的 MCP schema 顶层禁止 allOf/if/then（第三方网关会静默丢工具），**不能**直接用 `model_json_schema()` 生成。方案：契约文件内手写「约束子集 JSON Schema」+ 契约测试断言它与 pydantic 模型的字段名集合、required 集合双向一致，且不含顶层组合器。

## 五、节点注册表（消灭 C1/C3/C4）

```python
# nodes/registry.py — 唯一顺序真相
@dataclass(frozen=True)
class NodeSpec:
    key: str; label: str                    # 中文标签，供 meta API
    kind: Literal["code", "ai"]
    executor: Callable[[], NodeExecutor]
    requires: frozenset[str]                # 数据依赖（DAG 校验+最小交接）
    output_model: type[BaseModel] | None
    retryable: bool = False                 # from_node 重试白名单
    timeout_seconds: int | None = None      # 如 profile 600
    run_when: Callable[[Inputs], bool] | None = None      # 声明式出口 A
    gate: GatePolicy | None = None          # audit 的三值 gate 语义
    skip_verdict: SkipPolicy | None = None  # 被跳过时的 verdict/status 映射（出口 B/D）
    on_failure: Literal["fail", "preserve_gate_outcome"] = "fail"  # report 专用
    resume_check: Callable[..., bool] | None = None        # source 重拉检查
    tool_policy: ToolPolicy | None = None   # AI 节点工具白名单/Bash 黑名单（同步进镜像）
NODES: tuple[NodeSpec, ...] = (source, profile, env_ready, audit, reproduce, report)
```

**派生关系**：orchestrator `NODE_ORDER` ← `[s.executor() for s in NODES]`（保留模块级名字与单例形态，现有 `patch.object(NODE_ORDER[0],...)` 测试不破）；service `_NODE_INDEX`/`_RETRYABLE_FROM_NODES` ← NODES；ai_runner 校验分派 ← `output_model`；`_mock_output` ← 各 contract 的 mock 工厂；run_one `NODE_AI_KEYS`/`_allowed_tools_for`/`_classify_bash` ← `tool_policy`（构建期生成 JSON 打进镜像）；前端 NODE_ORDER/NODE_LABELS ← 新增 `GET /api/meta/nodes`（registry 序列化，前端静态值改拉取+fallback）。

**编排器泛化**（删掉 6 处硬编码分支）：非 web 出口 → `run_when=lambda i: i.profile.is_web is True`；gate 出口 B/D → reproduce 的 `run_when=lambda i: i.audit.gate_verdict == "pass"` + audit 的 `skip_verdict`（fail→false_positive；uncertain→任务 needs_review 且 report 仍跑）；report 失败保留结论 → `on_failure="preserve_gate_outcome"`；source 断点重拉 → `resume_check=source_tree_present`。循环体只剩通用逻辑。

## 六、配套解耦

1. **verdict 领域下沉（C5）**：新建 `agent/verdict.py` 收拢 `authoritative_verdict`/`document_kind_for_verdict`/`apply_poc_to_report_output`/`_VERDICTS`/`_CONFIRMED_VERDICTS`，ai_runner（留 re-export 兼容期）、report.py、tasks.py 改为引用一处。
2. **服务注入（C6，渐进式）**：`NodeServices` 聚合（project_cache / lab / node_run_writer）由 tasks.py 构造注入 NodeContext；env_ready 的 `_bump_node_attempt` SQL 直更改走 node_run_writer。不强制一次性迁完所有 DB IO。
3. **目录结构**：`nodes/<key>/__init__.py`(executor) + `contract.py`(模型+校验+mock+MCP schema) + `SKILL.md`；SKILL.md 构建期复制到镜像 `node-skills/<key>/`。
4. **镜像同步**：构建脚本从 backend 节点包收集 contract/MCP schema/tool_policy 生成 `runner/node_schemas.py` 等产物；保留现路径的兼容 re-export（后端测试 sys.path 引用不破）。

## 七、新增节点 SOP：11 处 → 3 处

改造后新增节点 = ① `nodes/<key>/` 一个自包含包（executor+contract+SKILL.md+mock）② `registry.py` 加一行 ③ CI 重建镜像。前端零改动（meta API）；orchestrator/ai_runner/service 零改动。

## 八、分阶段实施路线（每阶段独立可合并、测试全绿）

- **P1 契约层（先出参）**：各节点 `contract.py` Output 模型 + 迁移 `_validate_*`（错误文案逐字不变）+ mock 工厂迁出 ai_runner；`validate_output` 改查模型分派。风险对策：needle 断言不动即证明迁移无损。
- **P2 注册表**：NodeSpec/registry 落地，NODE_ORDER 等四处改派生；tool_policy 构建期同步 + 契约测试（字段/required 双向一致、无顶层组合器）。
- **P3 类型化交接 + 编排泛化**：requires/inputs 解析、节点内改 typed 访问、run_when/gate/skip_verdict/on_failure 声明化，orchestrator 循环去分支。
- **P4 领域与服务解耦**：verdict.py 下沉、NodeServices 注入、前端 meta API。
- **P5（可选）**：并行调度铺垫——requires 已声明，换拓扑调度器不动节点。

**测试风险对策**：错误文案与 API/序列化形状是回归门禁，全程逐字/逐形保留；NODE_ORDER 单例与 `patch("...ai_runner.run_ai_node")` 字符串路径保留；NodeRun 表零 migration。
