## 一、SECURITY.md 内容结构

**1. 支持的版本**
- 表格形式,仅支持最新版:v1.0.x(当前 v1.0.1)✅;更早版本 ❌ 不支持,请先升级
- 说明安全修复只在最新补丁版本发布

**2. 报告漏洞(核心章节)**
- 指引使用 GitHub 私密漏洞报告:`Security` 标签页 →「Report a vulnerability」
- 明确要求**不要**通过公开 Issue、PR、 Discussions 报告漏洞
- 建议报告包含:影响版本、复现步骤、影响评估(如凭据泄露/沙箱逃逸的利用后果)、修复建议(可选)

**3. 处理流程与时间线**
- 72 小时内确认收到
- 7 天内完成初步评估(是否受理、严重程度)
- 视严重程度在 30 天内发布修复(严重问题优先)
- 修复发布后通过 GitHub Security Advisory 公开,并致谢报告者

**4. 报告范围**(针对本项目的关键章节——Crucible 是漏洞验证平台,需划清界限)
- ✅ 纳入(Crucible 平台自身的漏洞):
  - 认证/授权绕过(JWT 伪造、跨用户越权访问任务/报告/Lab)
  - 凭据泄露(LLM API Key、任务凭据经日志、API 响应或容器环境外泄)
  - Agent 沙箱逃逸(agent-runner 容器突破隔离触及宿主或平台服务)
  - Lab compose 策略绕过(绕过 privileged/host 挂载/docker.sock 等禁令)
  - LLM Provider SSRF 防护绕过
- ❌ 不纳入:
  - **Crucible 在目标仓库中分析出的漏洞**(这是产品功能产出,不是平台缺陷)
  - 第三方依赖的漏洞(请报告上游;可同步告知我们评估影响)
  - 使用默认凭据(`crucible_secret`/`minioadmin`)且暴露公网的开发实例(README 已明确警告)
  - 偏离文档的部署导致的问题(如生产未设 AUTH_SECRET)
  - DoS、暴力破解、社会工程

**5. 安全部署提醒**(简短)
- 生产环境必须设置 AUTH_SECRET、修改基础设施默认口令
- 不要将开发实例暴露公网,详情见 README「凭据与安全」

## 二、配套步骤

1. 尝试用 `gh api` 为 `pgnzbl-ux/crucible` 开启 Private Vulnerability Reporting;若 API 不支持该设置,输出手动步骤:仓库 Settings → Code security and analysis → Private vulnerability reporting → Enable
2. 在 README.md「凭据与安全」章节末尾追加一行,链接到 SECURITY.md(便于发现,GitHub 也会在 Security 标签页自动展示)
