# README 第一视角

改写或新建任何 `README.md` 时必须遵守。

## 原则

用第一人称写**系统现在是什么**。禁止写演变史、进度账、本次 diff 的实现细节。

动笔前先问：读者按这段话去做，会不会做错或看错？会 → 改；只是记录「我们刚改了什么」→ 不写。

## 该改

- 与现状不符、读者会踩坑的事实（端口、路径、启动步骤、现有能力）
- 目录树与真实仓库对齐
- 使用步骤与当前 UI / API 对齐

## 不该写

- 已完成清单、P0/P1/P2 勾选、「已落地 / 真正生效 / 遗留 / 旧版 / 兼容保留」
- 事件类型名、内部字段、路由 path、Tab 名（除非读者调用 API 必须用到）
- 「曾经 / 替代 / 不再 / 注意这是修复」类对照

## 路线图

README **只列尚未做完的事**。已落地能力写在特性 / 流程 / 结构里，不在路线图打勾。

```
❌ 任务详情经 SSE 回放 agent.thinking，失败含 title + 下一步
✅ 任务详情通过 SSE 展示节点进度与 Agent 过程

❌ 旧单体 agent，保留兼容
✅ 目录只列当前使用的子 agent

❌ 单元测试为 P1 backlog
✅ pytest tests -k "not smoke"（测试已存在时）
```
