## 二、用户确认的关键决策

1. **Agent 两阶段解耦**：靶场环境搭建（`run-project-env`）与漏洞验证（`vuln-verify`）拆分为两个独立 skill / 模块，两个步骤解耦、可独立管理。
2. **P0 风险认可**：`R-01` Alembic 迁移缺失、`R-03` Runner 权限边界、`R-04` 凭据注入隔离、`R-05` 跨用户访问控制列为最高优先级。
3. **后端端口统一 8010**：防止与其他项目冲突；`main.py` 直接运行入口默认 8000 属已知偏差，后续应统一到 8010。

## 三、已识别风险点（详见 `docs/harness-repo-analysis.md` §8/§11）

**P0（必须优先处理）**
- R-01 Alembic 环境存在但未见迁移版本文件 → 生产 schema 演进、回滚、审计不可控
- R-02 Agent 任务跨 Celery/asyncio/Docker/Redis/DB → 取消、超时、事件一致性与清理易出边界故障
- R-03 Runner 工具权限与 Bash 黑名单决定安全边界 → 误放行扩大 Agent 破坏面
- R-04 凭据注入、临时目录与容器挂载跨多模块 → 凭据泄露或跨任务污染
- R-05 报告读取/发布 owner 校验需核验 → 可能跨用户数据访问

**P1**
- R-06 敏感配置与生产默认值依赖环境治理
- R-07 报告 artifact、Redis、SSE 失败降级规则分散
- R-08 报告页按任务逐条查询报告（N+1）
- R-09 前后端端口配置不一致（本会话已统一到 8010 约定，代码侧待跟进）
- R-10 前端缺少项目自有测试，API 类型手工同步

**P2**
- R-11 模块间直接导入模型/服务、全局单例较多
- R-12 缓存/构建产物边界需进一步确认

## 四、推荐后续改进项

1. **补齐 Alembic 迁移基线**：为现有 models 生成首个可追溯迁移版本，建立 `upgrade/downgrade` 闭环（对应 R-01）。
2. **统一后端端口到 8010**：修改 `main.py` 直接运行入口与启动文档，消除 8000/8010 不一致（对应 R-09）。
3. **落实 Agent 两阶段解耦**：将 `run-project-env` 与 `vuln-verify` 拆分为独立可管理模块，各自维护 skill、依赖与测试。
4. **补 owner 隔离测试**：为 reports/task/settings 各读取与发布接口补充跨用户访问控制测试（对应 R-05）。
5. **引入前端测试与契约**：接入前端单测/组件测试，评估 OpenAPI→TS 类型生成（对应 R-10）。
6. **审计 Runner 权限边界**：对 Bash 黑名单、allowed_tools、容器 user/网络做专项安全评审（对应 R-03/R-04）。
7. **建立交付验证基线**：为 Agent 主链路（创建任务→容器执行→事件流→报告）补充自动化端到端冒烟（对应 R-02）。
