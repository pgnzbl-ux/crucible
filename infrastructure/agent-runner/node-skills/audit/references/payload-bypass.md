# WAF / Filter Bypass 与白盒 payload 构造

当用户输入与 sink 之间隔着请求过滤器 / WAF / ORM / 模板墙时读本文。在 GATE 构造 payload **之前**读。

## 金科玉律：白盒读防御，不要黑盒试探

WAF 的行为完全可以从代码得知。发第一个探测请求之前：

1. **定位过滤类**——它经常不在项目源码里，而在**依赖 jar**（`ms-base`、某 Spring starter、Shiro interceptor）。从**本地**构建缓存或依赖树里解包/反编译读取（容器内 `~/.m2`、`node_modules`、`venv` 都是合法的本地文件）。禁止碰运行中的靶场容器。
2. 读它的**关键字表、符号表、匹配算法、大小写敏感性、作用的层**（匹配请求参数值？还是拼装后的 SQL 串？还是两者）。
3. 写下哪些组合会触发拦截。多数自研 WAF 是"**关键字 AND 符号同时出现**"型规则（如 `SqlInjectionUtil`：`\b(keyword)\b` 与 `(`、`--`、`/* */` 同时存在才拦，忽略大小写）。规则一旦读到，绕过就是机械推导。

黑盒一个关键字一个关键字试探既烧轮次又摸不全规则；读一遍代码得到整条边界。

## 经典绕过手法（逐条映射到它击穿的规则）

| 手法 | 示例 | 击穿 |
|---|---|---|
| 内联注释切分 | `SEL/**/ECT`、`UN/**/ION` | 要求连续关键字的子串/正则匹配 |
| 大小写变化 | `UnIoN SeLeCt` | 仅大小写敏感匹配（`containsAnyIgnoreCase` 无效） |
| 块注释截断 | `payload/*` | 需要闭合 `*/`；未闭合的 `/*` 常死于 JDBC 驱动（Druid） |
| 行注释截断 | `payload-- ` / `payload#` | 只截到行尾——多行 SQL 无效 |
| MySQL 版本注释 | `/*!50000UNION*/` | MySQL 照常执行，部分 WAF 解析错 |
| 编码 | URL / hex / unicode | 扫描原始字节而非解码值的 WAF |
| 表外词 payload | 纯表名；关键词表没收录 `union`/`from` 时直接用 | 遗漏结构词的黑名单 |

**关键：bypass 必须穿过每一层。** 骗过请求层 WAF 的 payload 仍可能死于 JDBC 驱动（Druid 剥 `/**/`、拒绝未闭合 `/*`）或 SQL 解析器本身。上线之前在纸上过完全部层。

## 白盒 payload 构造法（GATE 步骤）

对每个注入点，发 HTTP 之前在纸上回答：

1. **我的值落在哪？** 找出值被拼接进的每个子句位置（SELECT 列表 / FROM / JOIN / ON / WHERE / ORDER BY / LIMIT）。同一个参数可能出现在**多个位置**。
2. **每个位置要求什么？**
   - SELECT 列表 → 只能是列表达式（不能带 ON/JOIN/FROM/UNION/派生表）
   - `ON x.col` → `x` 必须是裸标识符且该表有列 `col`
   - WHERE 值 → 可以携带 UNION（UNION 跨 WHERE 连接两个 SELECT）
   - ORDER BY → 不能携带 UNION（UNION 绑定 SELECT；ORDER BY 在语句末尾）
3. **位置之间冲突吗？** 同一个值既要当裸表名（供 `x.*`）又要当 JOIN+ON 表达式 → 没有单一字符串同时满足 → **结构性阻断**。
4. **能截断余部吗？** 塞 UNION 通常要注释掉注入点之后的一切。检查：单行 SQL（`--`/`#` 到语句尾）还是多行（需要 `/* ... */` 且闭合 `*/` 必须存在——硬编码尾段通常不给）？驱动是否容忍你选的注释形态？
5. **哪层防御杀它？** 对照第 1 步的 WAF 规则与驱动/解析器行为逐层核查。

同一方法可推广到任意 sink：映射输入落点、各位置约束、约束是否冲突、余部能否截断。**冲突或余部不可截断 = 结构性阻断。**

## 何时停手并判结构性误报

第 1-5 步证明**没有任何 payload 能同时活过所有位置与所有层**时，该注入点**结构上不可利用**——在 GATE 判 `fail`。禁止：

- 继续轮换绕过语法指望蒙中一面——墙是**结构**，不是 WAF；
- 因为"输入确实到了 sink"就滑向"部分确认"——可达 ≠ 危害；
- 向靶场造数据制造可见结果——那是篡改靶场。

真实的代码弱点（非参数化拼接、可绕 WAF）仍可作为 defense-in-depth 记录——但它不是可利用漏洞，不得按漏洞口径报出。
