# CWE-89 SQL 注入 微评分表

## 高风险模式
- 字符串拼接/格式化构造 SQL（f-string、%、+ 拼接）
- ORM 的 text()/raw SQL 直接纳用户输入
- 排序字段/表名/列名来自请求参数

## 安全惯用法
- 参数化查询/预编译（?、%s、:name）
- ORM 的表达式 API（filter/where 绑定值）
- 白名单枚举映射动态标识符

## 伪消毒器（看似净化，实则可绕过——误判重灾区）
- 仅 strip/trim 字符串就当消毒
- 手动转义单引号（\' 或 ''）后拼接
- 类型断言后仍走拼接路径
- 依赖 WAF 拦截

## 引导问题（依次回答后再下结论）
1. 污点数据的真实来源是什么？是否攻击者可控？
2. 从入口到危险点之间有哪些净化/校验？对照上方伪消毒器清单逐条排查。
3. 该路径是否真实可达（挂在有效路由/入口之后，且配置启用）？
